# Design

## Context

See `proposal.md` — Why and `specs/canvas-empty-state/spec.md` for the behavior contract.

Relevant current state of `packages/form-components/src/components/wb-canvas/`:

- `wb-canvas` compiles with `shadow: true`, so host children (light DOM) are only displayed if the shadow template renders a `<slot>`.
- `render()` returns a `.wrap` container that is assigned to `this.listEl` and is the single drop surface. Palette drags are hit-tested geometrically: `setExternalHoverIndex` uses `this.listEl.getBoundingClientRect()` for the vertical bounds, `getInsertionIndex` reads `:scope > [data-element-id]` rows, and `computeColumnDropTarget` scans `[data-container-id]` / `[data-column]` descendants.
- The element list is reactive state (`@State() fields: FieldMeta[]`), so the shadow template already re-renders when it changes.
- `wb-canvas` currently has no `<slot>` anywhere, and no other component in the repo uses slots.
- The React wrapper generated by `@stencil/react-output-target` delegates to `@lit/react`'s `createComponent`, which passes `children` through to the custom element as light DOM; therefore a default slot is reachable from React `<WbCanvas>…</WbCanvas>` without any generated-code change.

## Goals / Non-Goals

**Goals:**

- Show host-provided children as canvas default content exactly when the top-level element list is empty.
- Keep the canvas a working palette drop target while that content is visible, including the top-level drop indicator and insertion at index 0.
- Guarantee zero visual change for existing hosts that pass no children.
- Give hosts a CSS hook to size the empty region without forcing a size on hosts that don't want one.

**Non-Goals:**

- Named slots or multiple content regions.
- A built-in placeholder/illustration rendered when no children are supplied.
- Changing drag, insertion, selection, or `wbChange` semantics.
- Changing row-container empty-column behavior (existing `.empty-slot` strips stay as they are).
- A `@Prop()`/attribute to enable or disable empty content (see D3).

## Decisions

**D1 — Use the unnamed `<slot>`, rendered conditionally, as the opt-in.**
`render()` gains `{this.fields.length === 0 && <div class="empty-state"><slot /></div>}` as a child of `.wrap`. Passing children is the opt-in; there is no separate flag. *Why:* the request is literally "show the passed children", and an unnamed slot maps directly to React `children` (already forwarded by the wrapper) and to plain-HTML light DOM. *Alternatives considered:* a named slot (`name="empty"`) — more future-proof if the default slot is ever reused, but it requires consumers to set `slot="empty"` and contradicts "passed children"; a VNode/HTML prop — not idiomatic for Stencil and would bypass the light-DOM composition model.

**D2 — Render the slot inside `.wrap` (the `listEl` drop surface).**
`.wrap` is the geometric hit target for palette drags; placing the empty content inside it grows the hit rectangle to match whatever the host renders and keeps the content inside the existing scrollport and padding. *Why:* the canvas must remain a drop target. *Alternative considered:* rendering the slot as a sibling of `.wrap` — rejected because drag hit-testing and scrolling are scoped to `.wrap`, so the content would fall outside the drop surface.

**D3 — Presence of children is the switch; no `@Prop()` toggle.**
The slot renders whenever `fields.length === 0`; when no children are passed it projects nothing and the `.empty-state` wrapper contributes no height by default. *Why:* avoids a second source of truth (a boolean prop that can desync from whether children exist) and preserves existing blank-canvas behavior for current hosts. *Alternative considered:* `showEmptyState`/`emptyContent` prop — rejected as redundant and more API surface.

**D4 — Empty content is excluded from element hit-testing by construction.**
The `.empty-state` wrapper carries no `data-element-id`, `data-container-id`, or `data-column`, so `getInsertionIndex` (`:scope > [data-element-id]`) and `computeColumnDropTarget` ignore it and the insertion index stays `0` on an empty canvas. No drag code changes are required beyond rendering inside `.wrap`. *Why:* keeps the drag implementation untouched and low-risk. *Alternative considered:* filtering slots out of the drag selectors — unnecessary because the selectors are already element-id based.

**D5 — Sizing via `--wb-canvas-empty-min-height`, default `0`.**
`.empty-state` gets `display: flex; flex-direction: column; min-height: var(--wb-canvas-empty-min-height, 0);`. Hosts that want a large drop surface set the variable; hosts that pass nothing get no phantom box. *Why:* matches the repo's existing CSS-custom-property convention (`--wb-canvas-remove-color`, palette/inspector vars) and keeps the default visually neutral. *Alternative considered:* a fixed default min-height — rejected because it would change the current blank-canvas rendering for hosts that never opted in.

**D6 — Leave `onWrapClick` deselection unchanged.**
A click on the empty content bubbles to `.wrap` and is treated like a click on empty canvas (deselect if something was selected). In the empty state there is normally no selection, so this is unobservable; special-casing slot content would add complexity for a case the request does not raise.

**D7 — Testing split: unit + dev harness.**
Unit tests assert the shadow `slot` is rendered when `fields` is empty and absent once a field exists, and that an empty canvas still resolves the top-level drop target/inserts at index 0. Actual slot projection in `mock-doc` is unreliable, so real projection is validated in the dev harness (and browser tests if a slot projection case is added later).

**D8 — Full-height canvas with centred empty content.**
`:host` becomes `display: flex; flex-direction: column; height: 100%; min-height: 0`; `.wrap` becomes `flex: 1 1 auto; min-height: 0` and drops its old `max-height: 60vh`; `.empty-state` becomes `flex: 1 1 auto; align-items: center; justify-content: center`. *Why:* the empty region must be able to use the whole available height for centring while the field list keeps scrolling inside the surface, and the canvas must size to the height its container provides. *Trade-off:* removing `max-height: 60vh` means an unconstrained canvas grows with its content instead of capping the scroll box; hosts that want a bounded canvas give it a definite height (now filled) or set a height on the host. *Alternative considered:* keeping `max-height: 60vh` — rejected because it stops the surface from ever filling a taller container and leaves the content centred in a short box rather than the available region.

## Risks / Trade-offs

- [Mock-doc may not project slotted children, making a projection assertion flaky] → assert `slot` presence/absence in the shadow root for unit tests and verify actual projection in the dev harness/browser.
- [Host places interactive content in the empty state and a click also deselects] → documented; empty content is intended as presentational default content; D6 can be revisited if a real interactive case appears.
- [Rendering the slot only while empty means children disappear the moment a field is added] → this is the specified behavior ("when there are no fields to display"), and the field list replaces the content.
- [Host passes children but never sees them because a field already exists] → expected per spec; the slot is intentionally hidden when non-empty.
- [The canvas no longer caps at `60vh`, so an unconstrained host grows with its content] → hosts should give the canvas a definite height (the layout fills it); documented in the package readme and demonstrated in the dev harness by stretching the canvas in the layout.

## Migration Plan

Additive apart from the canvas layout change: a new default slot and a new CSS custom property, and the surface now fills available height instead of capping at `60vh`. No existing props, events, methods, or markup change. Hosts that relied on the scroll cap should give the canvas a definite height. Rollback is a revert; hosts that pass no children are unaffected by the slot.

## Open Questions

None blocking. Whether to add a browser (`.cmp.test.tsx`) projection test or only a dev-harness demo is an implementation detail to settle in tasks.
