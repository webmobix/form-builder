form-components dev harness

Manual smoke test: click a palette item to add a field (inserts after the selected component, or appends when none is selected), drag the grip handle to reorder, select a row to edit in the inspector, submit the form.

How it wires together
  1. Add from palette: clicking a palette item emits wbAddField; the script calls canvas.addFieldAfter(type, label, subtype, design). Dragging emits wbPaletteDragStart/Move/End, which the script forwards to canvas.beginExternalDrag(), setExternalHoverIndex(x, y), then commitExternalInsert(...) (or cancelExternalDrag()).
  2. State broadcast: the canvas emits wbChange with the full FieldMeta[]; the script stores it (lastBuilderPayload), shows it, and pushes it into the renderer via renderer.setFields(payload).
  3. Select & edit: selecting a row emits wbFieldSelected; the script records the id and calls inspector.setField(field). Clearing the selection emits wbFieldDeselected → inspector.setField(null).
  4. Apply edits: the inspector emits wbFieldUpdated with { id, patch }; the script calls canvas.updateField(id, patch), which applies it (even nested in a row) and re-emits wbChange.
  5. Submit: the renderer emits wbSubmit with the form data as Record<string, string>, displayed in the payload panel.
  6. Import / export: dump-builder shows the stored payload; export-json downloads it; load-into-canvas parses the textarea/file and calls canvas.importState(parsed), which replaces the canvas state and re-emits wbChange.
